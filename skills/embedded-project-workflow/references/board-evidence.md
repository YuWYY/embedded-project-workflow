# 板级资料、参考工程与适用性

用于会改变引脚、DDR、PS 外设、板载时钟、复位、电气配置或启动方式的任务。先读当前工程和已有材料；普通算法、小范围 RTL 修改无需先收齐整板资料。实现选择另见 [IP 选型](ip-selection.md)，SoC 接入见 [Zynq/MPSoC](zynq-mpsoc.md)。

## 按设计依赖取得事实

从工程 part、board_part、约束、配置及已有成功版本提取事实。只询问仍缺失且影响本次设计的内容：商品链接与完整型号；核心板/底板组合和各自硬件版本；芯片完整料号；相关原理图、手册和参考工程。用户已提供的信息不重复询问；没有商品链接的自研板可直接以设计资料为依据。

按当前功能定位到资料页和信号：例如 DDR 型号/位宽/连接、参考时钟来源、MIO/EMIO、I/O Bank 电压、复位关系。不要让用户逐项猜寄存器。缺 DDR 依据时标明受阻的配置和原因，同时推进不依赖 DDR 的逻辑、接口契约或离线仿真；不把未知项补成其他开发板的数值。

## 主动寻找匹配实现

优先比较当前已成功工程、对应板厂官网/仓库、AMD 官方板文件与参考设计，再评估其他开源实现。实际匹配程度优于来源排名：同芯片不等于同板；核心板相同也不保证底板连接相同。商品名称相似、仓库热门或“官方示例”不足以证明适用。

对候选只记录本次需要的内容：

| 依据 | 要核对的内容 |
|---|---|
| 板卡匹配 | 核心板、底板、硬件修订、完整 part、内存与涉及的外设连接 |
| 工程匹配 | Vivado/Vitis、board file、IP 和 SDK 版本；配置入口与依赖 |
| 采用范围 | 复用哪些配置或模块；哪些板级差异必须修改；需要保留哪些用户逻辑 |
| 许可和来源 | 原始链接、核查日期、可取得的固定提交、文件许可；未取得提交时明确记录，不能将 tag 当 commit |
| 成功证据 | 原作者在哪块板上报告何种结果；本地实际生成/构建结果；目标板实际结果分别列出 |

例如 [Xilinx Board Store](https://github.com/Xilinx/XilinxBoardStore) 可提供板文件，但应读取实际版本的 board.xml、preset 及适用硬件修订。board file 的文件版本和硬件 revision 是不同事实。安装包内来源记录和文件哈希可以固定本地实际输入，不代表已经复核远端最新提交。

## 冲突与采用

原理图、手册、preset、当前工程相互冲突时，指出涉及信号/属性、各自来源及会改变的行为。不能因一份资料更新或来源官方就直接覆盖另一份；先检查是否对应不同修订、不同器件或原工程有意修改。需用户确认实物版本时提出最少问题，继续无依赖工作。

在授权范围内使用匹配的原生配置。已有定制 PS 配置不能因为找到了 preset 就全部重套；按差异决定保留和修复。需要借用开源模块时同时检查接口、依赖和许可，不复制孤立 HDL 后忽略原有约束。

源资料中的“已测试”保留为原作者声明；本地工具通过保留为本地证据；只有实际目标板验证才能写为板测通过。不将某个参考板的 DDR、引脚、频率或启动配置作为 Skill 通用默认值。源码阅读和工具配置不授权下载、通电或连接调试器。
