# 同一工程的两张规划图

用于完整项目规划（新建或既有工程整体规划）、全局架构重规划，或用户明确要求规划图。交付一对视图：**引脚功能图**说明外部接口与用途，**执行逻辑图**说明内部职责、数据流和执行条件。两图使用同一工程、同一配置版本及相同对象名称；不把五个参考模板全部当成交付。已定位的小代码修改、首次只读概览不增加制图流程。已有实施授权继续有效，完成规划和图后继续已授权工作，不新增“看图批准后才能实施”的门槛。

## 先确定图所依据的事实

读取本轮相关的最新原生配置、源码、原理图及约束，记录实际来源和版本；用户已明确的设计要求可作为拟议方案依据。图旁简记“拟议 / 已由配置或源码确认 / 已实测”，分别标注局部状态，不能用整图的“已确认”覆盖未决部分。

- MCU：由原理图、`.ioc`、当前GPIO/外设初始化及器件资料核对GPIO、外设通道、方向与用途。物理脚号和AF编号仅在本次确需时补充，且须由对应器件与封装资料确认；确需但未确认的字段标“待核实”，不从相近芯片补齐。未定的关键GPIO分配或外设功能必须标“待确认”；不为每个已知GPIO标签附加无关的物理脚号/AF缺口。
- FPGA：核对当前顶层端口、RTL方向、XDC中的`PACKAGE_PIN`和`IOSTANDARD`及对应板级连接。名称、封装脚、方向或电气标准有缺口时逐项标“待确认”；冲突保留双方来源并标“冲突待解”，不猜可用引脚或默认为某电平标准。
- 尚未实现的模块、周期、预算和连接标“拟议”。配置、源码或仿真能支持的事实不能写成板载实测；没有测量就不填实测耗时或精确调度轨迹。

图是配置与方案的派生视图，不成为新的配置源或全量参数副本。用户删除、重命名或修改对象后，先重读最新配置，再同步两图中受影响的名称、引脚、职责及连线；保留用户改动，不能从旧图或模板把对象恢复回来。

开始排布前，沿本次相关源码或接口约定确认“对象、来源、谁发出、谁接收、何时发生、哪些未知”。在绘图源码的共用名称或已有说明中保留这一对应即可，不另建工程配置格式。数据、请求、完成通知、时钟与复位分别核对；框里写了正确名称，不代表连线关系也正确。两图共用确认后的名称与参数，不把模板的具体关系复制成当前设计。

## 两图共用的画法

白底、简单矩形、清楚的文字层级；对象尽量按数据方向排布，给标签留空间。芯片画成抽象功能矩形，周边排列接口；它不是封装俯视图，不按示例位置推断真实物理引脚顺序或器件几何。

连线只走水平或竖直段，每条线写实际信号或总线名称；箭头指向实际接收端，返回握手按实际方向单独表达。端点落在真实模块或端口，交叉不自动表示连接；仅真实电气/逻辑汇合点加实心圆点。避免线穿文字或模块，必要时人工调整位置和折点。

排布时先给模块之间及模块外侧留出走线空隙，回调、完成通知等返向路径沿空隙绕行，不走过无关模块。长函数名、总线名在标签区域换行或扩大间距，不能越过框线；多个关系拥挤时调整模块位置，不以遮住线或缩成难读小字解决。背景、范围框先绘制，后续矩形不能盖住已写的注记。

| 线的含义 | 颜色 | 同时写出的文字 |
|---|---|---|
| 数据 | 蓝 | 数据/总线名、必要宽度或单位 |
| 控制、触发、握手 | 绿 | 使能、事件、请求/完成等实际含义 |
| 时钟 | 橙 | 时钟名、已确认频率或“待确认” |
| 复位 | 红 | 复位名、极性及必要的复位范围 |

颜色只辅助识别，不能代替标签。虚线框仅表达并注明范围，如CPU/硬件、任务组或时钟域；**信号不得终止在虚线框边界**。端点必须继续到实际模块/端口；共有时钟与复位也可用明确的域内公共注记，不能画一根线到范围框冒充所有对象已经连接。

## 引脚功能图

按当前接口用途分组：例如采样、功率控制、通信、显示、时钟或调试。每组写真实端口/GPIO、外设功能、方向和连接对象；已知的物理脚号、AF或I/O标准可附在同一标签中。只呈现与方案有关且有依据的分配，不为“填满芯片四周”虚构引脚。

芯片内部可列相关外设或FPGA顶层接口，外部矩形是实际传感器、驱动器、收发器或连接器。电源与地、双向总线和差分对按真实电路语义标注；单向箭头不能把双向接口误写成单向。引脚图与逻辑图中的接口、模块名和输入输出关系应能相互对照。

## 执行逻辑图按实际实现选一种

### MCU裸机

区分初始化、主循环、硬件链路和ISR。硬件定时器触发ADC、DMA搬运和中断回调按真实触发与完成关系连接；DMA搬运不画成CPU逐点复制，硬件触发不画成主循环定期调用。主循环只放实际轮询、状态机或后台处理。未采用RTOS就不加入任务、调度器或队列以填模板。

### MCU与RTOS

每个实际任务写职责、触发周期或事件、有效优先级及语义；核对本工程FreeRTOS/CMSIS映射，不能把任务优先级和NVIC优先级混用。用通知、队列、信号量或共享数据连接实际生产者与消费者，保留独立硬件、DMA和ISR链路。

CPU执行预算、测得耗时、未知耗时分开标注；周期、阻塞等待/超时和完成期限分别表达，不能把阻塞时间当CPU占用，也不能把周期当已保证的截止期限。可表达先后依赖和唤醒条件；无可信轨迹时不画声称精确的任务运行时间线。具体分工与对象来源见[FreeRTOS](freertos.md)。

### FPGA单时钟域或多时钟域

主要模块分别成块，呈现并行硬件和模块间数据/握手关系。**每个主要模块直接注明自己的执行条件**，例如“每个CLK上升沿”“有效使能时”“每20 ms锁存一次”或“请求且非busy时启动”；这些条件必须来自本项目，20 ms不是模板默认值。不能仅写全图通用“并行运行”而省略各模块的实际条件，也不画逐时钟格子或CPU任务优先级表。

虚线域框写时钟域名称；域内公共注记可写`CLK=...`、频率和共有复位。不同复位作用范围、极性或同步释放关系单独注明，不能因处于同一时钟域就推断所有模块同复位。模块自己的时钟使能、采样事件、分频或握手条件仍直接写在模块中。

复位极性也必须有配置或实现依据；只有顶层连接或接口名时，不能凭`rst`、`rst_n`或模板确定极性。能确认连接而不能确认极性时如实标“极性待确认”，仍完成其他已确定关系。

异步FIFO放在两个域的边界，写侧/读侧明确标各自时钟和复位，数据流从写域模块进入FIFO、再从FIFO到读域模块；写使能/满、读使能/空及其他握手方向按真实接口画。若实际FIFO只有一个复位入口，应如实标入口及其对两侧的作用，不虚构两个独立复位端口。跨域结构、复位及约束仍需按[Vivado指南](vivado-workflow.md)核查，图的整齐不证明CDC正确。

## 可编辑参考与输出

参考都在本Skill内，含有示例或待确认标记，使用时替换成当前工程事实：

| 用途 | SVG参考 |
|---|---|
| 抽象芯片与接口分组 | [引脚功能](../assets/planning-diagrams/01-chip-pin-layout.svg) |
| 主循环、硬件触发、DMA与ISR | [裸机执行](../assets/planning-diagrams/02-baremetal-execution.svg) |
| 任务职责、事件和执行预算 | [RTOS执行](../assets/planning-diagrams/03-rtos-execution.svg) |
| 单域并行模块及各自条件 | [FPGA单时钟域](../assets/planning-diagrams/04-fpga-single-domain.svg) |
| 两域与边界异步FIFO | [FPGA跨时钟域](../assets/planning-diagrams/05-fpga-dual-domain-fifo.svg) |

复制所需参考或[模板生成源](../assets/planning-diagrams/generate_templates.py)到当前工程的图稿目录，修改模块、标签、坐标与折线；选一张引脚图和一种适用执行图形成成对交付。共同绘图原语见[planning_canvas.py](../scripts/planning_canvas.py)，它提供简单画布、矩形、文字、范围框和折线，不是自动布局器，也不要求新增JSON配置框架。复制生成源时保持其对绘图原语的可用引用，或将原语一并复制到图稿目录后调整导入。

画布的 `block()` 可统一背景、标题、正文与留白；`text(max_width=..., line_height=...)` 可声明标签宽度与像素行距；默认行距仍为字号的 1.35 倍，不自动换行，换行由作者明确给出。`diagnose(font=已有字体)` 提示局部T形歧义、穿框、文字溢出和后画模块遮字，不修改布局、不判断电气连接。无字体或度量条件时相应检查为未执行；诊断为空也不能代替查看。先判断提示是否对应真实问题，再调整模块、标签或折点；合法交叉不需要为了消除提示添加假节点。

在Skill根目录运行模板生成示例：

```text
python assets/planning-diagrams/generate_templates.py --output <图稿目录> --format svg
python assets/planning-diagrams/generate_templates.py --output <图稿目录> --format both --font <已有中文字体文件>
```

SVG导出只依赖Python标准库。PNG是可选预览，仅使用已安装的Pillow和明确提供的现有字体，不安装软件或依赖固定机器路径；条件不足时保留可编辑SVG并说明PNG缺口。交付修改后的源稿和SVG；PNG可与SVG一起用于预览。导出后实际查看两张图，核对文字溢出、遮挡、折线、箭头、端点、域/复位边界及同名对象的一致性，按需要调整坐标重导出。

SVG与PNG必须来自同一份布局源：使用共同画布分别导出，或直接渲染最终SVG，不另写一套PNG坐标和标签。检查最终交付文件的实际显示，包含原尺寸和缩小预览；SVG在查看器中的字体回退、绘制顺序也可能造成压字。无法打开或查看时明确标为未完成图面复核，不能用XML解析、成功写文件或自己写的PASS文字代替。修订后重新导出受影响的SVG与PNG，不能只修预览。

首次向用户交付前，由执行者完成自检并自行修正。查看器自动缩图时，必要的局部须放大查看；最终检查对应最终文件，不能沿用修改前截图或检查结论。简记图稿身份、来源和未决项即可，不要求每轮新增报告。无关引脚未变时可保留原图内容，但仍确认其来源与当前设计兼容；配置变化使旧执行图或工具结果失效时应明确更新。

SVG/PNG导出成功只证明图稿输出；不能据此声称完成工具配置生成、固件构建、RTL仿真/实现或硬件验证。交付时简记图的依据、拟议/已确认范围与未决项，不附加无关报告流程。
