# 接手既有工程与结构变更

在已有任务、页面、接口或组件中新增功能，或接续用户结构修改时读取。已经定位的局部修改不需要重做工程接手。

## 找到本次功能真正经过的路径

先读当前工程与约定，沿一条相关功能链查明配置源、生成入口、用户实现和构建入口。例如采样任务→队列→处理任务，或控件交互→用户View→Presenter→Model。不先扫描所有外设或让用户重复填写已有资料。

分别识别明确约束、AI可调整范围、历史默认值及待确认事实。新任务中已明确允许新增页面等变化时，以当前约定为准；保留历史工程及其旧约定，不把旧约定静默改写成新授权。没有预设且已委托设计时，自主形成最小结构。

必要时在现有项目说明补一张短表：**本次功能｜有效配置源｜用户决定/允许范围｜用户实现位置｜实际验证入口**。值仍留在原生配置，不再同步一份全量参数文件。

## 先复用结构，再实现行为

检查功能由原生配置、已有组件或用户代码分别负责什么。沿既定任务、页面和接口接入，不通过隐藏线程、重复对象、另一个页面框架或旁路数据通道避开约定。

把交付终点写成可观察行为，例如队列消费者更新统计，或点击按钮清空窗口并保留暂停状态。生成、构建和运行各有自己的证据；构建通过仍可能只接入了默认空回调或弱任务。

建立成功基线后增量实施，先完成一条功能链。新增验证须能检查实际行为或相关接入；不要为每次改动重跑全部工具、增加逐文件审批或另建任务系统。

## 结构变化按其影响接续

读取最新原生设计，比较对象含义和依赖，不能只看文件名或哈希：

| 当前变化 | 相关接入与验证 |
|---|---|
| 任务职责、入口或通信对象变化 | 创建来源、生产者/消费者、数据生命周期、启动顺序及实际链接定义 |
| 新控件、交互或导航 | 原生触发和动作、生成回调、用户派生层、业务状态及跨页保留 |
| 队列元素类型或接口宽度变化 | 两端类型、复制长度、存储容量、适配及边界测试 |
| IP端口或静态参数变化 | wrapper、时钟复位、协议、约束及受影响的生成/构建 |
| 配置或组件变化 | 当前有效配置、构建引用、依赖及派生输出 |

授权范围内联动完成。遇到明确约束冲突，形成最小变更方案并继续独立工作；不恢复用户旧配置来获得通过。

工具支持的空虚函数、弱默认任务或未连接端口可能不导致构建失败。应核对实际调用和定义，并执行有鉴别力的业务或交互测试。缺失用户实现负例的预期取决于该机制，不强行规定所有负例必须编译失败。

## 区分示例重建器和既有工程入口

先检查执行脚本是否会创建模板、重写整段配置、覆盖用户文件或注入固定对象。此类脚本只用于它声明的示例准备，不能直接套到用户已修改的工程。

既有工程入口只读取当前工程，执行已授权的原生生成/构建并核对产物；不能附带恢复模板或同步示例代码。若生成器需要新增用户派生文件，核对其为工具支持的行为并检查原有实现保留，不一律把任何新增文件视为污染。

TouchGFX 4.26.1 Simulator工程可按[TouchGFX指南](touchgfx.md)使用随包的窄入口。CubeMX的现有栈/静态队列适配器仍只承诺其声明的操作。

## 脚本范围不是Skill的能力上限

脚本拒绝时，区分实际配置冲突、脚本未覆盖的布局/操作、版本未验证。后两者可依据实际工程和官方机制继续分析，通过原生工具形成当前项目的适配；不能编辑旧计划、取消检查或谎称原脚本已支持。

新机制先记录在当前项目，按[配置约定](configuration-contracts.md)核对来源与扩展位置。没有工具时可完成资料与用户代码，但生成、目标构建和运行保持未执行；模拟日志、手写派生文件及主机测试不能补齐这些层级。

## 交接

只保留目标、当前约定、有效入口、最近成功来源、未完成差异和下一步。新代理从当前文件继续，不预设用户结构已恢复或旧验证仍有效。准备原始输入与执行接手的代理应分离；评估者保留评分依据，执行者只获得请求、Skill和完成任务所需的原始工程材料。
