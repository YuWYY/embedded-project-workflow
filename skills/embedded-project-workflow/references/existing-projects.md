# 接手既有工程与结构变更

用于第一次读取、在已有结构接入功能或接续人工修改。已定位的小编辑直接处理相关文件。

## 先选对工程，再沿功能链读取

以用户本轮给定的根目录和配置入口为准。多个同名副本、多个入口或已有状态文件时，核对当前路径和入口引用；文件名相同、修改时间较新或旧聊天提到过，都不足以选择另一个副本。入口不唯一且任务无法确定时列出候选与差别，只问这一项，不开始完整访谈。工程有Git且版本关系影响本次判断时，读取分支/提交和相关差异；复用本轮已取得的结果。已确认无Git时用文件身份继续，不重复探测或初始化仓库。

只读入口不依赖厂商安装：

```text
python -B "<Skill目录>/scripts/project_intake.py" inspect --project "<当前工程根目录>"
python -B "<Skill目录>/scripts/project_intake.py" inspect --project "<当前工程根目录>" --entry "<根目录内相对入口>" --format json
```

首次只读概览时，Python可用且输入属于已覆盖格式，优先运行此入口取得可确认的对象和声明单位，再补读目标相关代码；具体字段仍有解释缺口时才读工具章节。它读取IOC、TouchGFX、XPR/BD及有限CMake声明，不配置、不生成、不编译。源文件中的版本不证明本机安装；未识别格式不证明工程无效。未知版本仍可提供能读到的信息，原生执行支持另按工具指南核对。不将来源摘要当第二套配置，不把解析通过当功能完成。

向用户说明数量时，带上已确认的原生单位和来源，例如栈的 words、队列的元素数、时钟的 MHz；不能只在工具输出里留下单位，最终概览却只列数字。已确认的配置声明可以直接报告，不因缺少生成树就丢掉已知单位；未核实的字节换算、最终内存分配或实际运行仍单独标为未验证。

沿本轮功能查配置源、生成入口、用户实现和构建接入，例如任务→队列→消费者，或控件交互→用户View→Presenter→Model。不先扫描所有外设。沿用[设计约定](configuration-contracts.md)，只补影响本次实现的缺口。

## 从概览到下一步

概览用当前文件说明工程入口、相关对象及单位、用户实现和构建接入、已知缺口。脚本只覆盖原生配置的有限字段，代码接入需继续读取实际源码，不能从解析成功推定存在。末尾给一个与用户目标有关的下一步：**做什么、在哪个真实对象/文件、预期看到什么、还缺哪个条件**。只读请求停在建议；已获实施授权则继续做，不为这条建议另开批准流程。未给功能目标时，下一步可以是定位一个相关实现，不擅自发明功能。

`PARTIAL` 时保留能确认的事实，再说明哪一条缺口影响下一步；缺引用先查声明路径和当前副本，格式未覆盖则按原生机制分析。`ERROR` 不等于整个工程无效。脚本给出的执行器提示只用于选候选入口，不证明本机工具可用或工程已满足执行条件。可调用入口及参数来源见[最小调用](execution-entries.md)，不让用户重新填写已经能从工程读取的字段。

## 接通行为而非只留下声明

交付终点要能观察，例如队列消费者更新统计，或点击按钮清空窗口并保留暂停。空虚函数、弱默认任务、未连接端口可能仍然构建成功，需核对真实调用、最终定义与业务结果。相关负例按机制设计，不强行要求所有接入缺失都编译失败。

功能需要累计运行时间时，区分底层tick的回绕周期、刷新间隔和累计量的范围。仅在回绕边界附近初始化，再测试短区间差值，不能证明运行满一个tick周期后累计量仍正确。执行者应在交付前以初始化后的连续有效采样跨过完整周期，运行实际业务源码并核对累计值、刷新边界及迟到行为；不必按墙钟等待，但相邻采样必须满足实现的间隔约定。独立复核是补充，不能把这一检查留给后续审阅者。实现若只支持有限时长，应明确上限并核对目标，不能以局部回绕自测代替长期累计契约。

沿现有任务、页面和接口实施，先完成一条功能链，再增量扩展。记录本次有效来源和验证入口即可；不复制全量参数或无变化的旧报告。

## 新增、重命名、删除分别处理

读取当前设计并比较含义，不能只比较名称和哈希：

| 用户变化 | 应接续的行为 |
|---|---|
| 新增对象或交互 | 先核对原生声明和生成入口，再补用户实现；默认空回调仍是未完成 |
| 重命名，行为保持 | 更新引用和适配，检查旧名残留的实际影响；不能另建旧对象或改回名字 |
| 明确删除对象或行为 | 清理受影响引用与接入，验证被删除行为不再执行；不把对象缺失当作必须恢复 |
| 修改职责、类型或宽度 | 核对生产者/消费者、复制长度、存储、生命周期和启动关系 |
| 修改IP静态参数、端口或连接 | 核对wrapper、协议、时钟复位、约束及受影响的生成/构建 |
| 只有格式、顺序或时间戳变化 | 判断语义是否改变；不因此重做全部实现 |

“名字不见了”不足以判断删除还是改名；优先结合当前差异和用户要求，无法确定且影响行为时再问。授权内联动处理；真实约束冲突按配置指南形成方案，不能恢复旧配置来通过验证。

## 区分准备器、检查器和执行器

运行前确认入口做什么。创建模板、重写整段配置、同步固定用户代码的脚本，只能用于其声明的示例准备；不可套到用户已修改的工程。只读检查器只说明观察；既有工程执行器应使用当前设计生成/构建，不能附带回灌模板。

原生生成器可能创建新增用户派生类；应核对工具机制并保护原有实现，不把任何新增文件都当污染。TouchGFX窄入口只生成/构建当前Simulator设计，业务仍需接入；CubeMX窄入口只改既有栈/静态队列参数；SoC脚本只检查交接元数据。能力和调用见[最小调用](execution-entries.md)，具体机制按相关工具指南读取。

脚本拒绝时区分配置冲突、脚本范围不足和版本未验证。后两者可按当前工程和官方机制继续分析，不改检查器结果、旧计划或派生产物来假装原入口已经支持。无工具时生成、目标构建和运行保持未执行，主机替身不能补齐。

## 交接

跨轮次按[长期任务指南](long-project-workflow.md)保留必要身份、差异和下一步，新代理从真实来源继续。评估接手能力时，准备输入与执行代理分离；执行者只取得请求、Skill和原始材料，不取得评分答案或前序结论。
