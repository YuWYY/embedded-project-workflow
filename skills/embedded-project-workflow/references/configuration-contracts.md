# 配置能力发现与用户设计约定

在新功能涉及工程结构、用户预配置、陌生工具或多个配置来源时读取。已经定位的局部修改不需要重新做架构访谈。

## 从目标发现工具能负责什么

读取当前工程、实际工具版本和用户资料，查找原生配置、生成标记、组件目录、构建入口及用户扩展。不要因为自己会写代码，就略过已有的配置能力；也不要因为存在图形界面，就要求把全部逻辑搬进去。

对本轮功能判断：原生工具能否表达；是否适合让用户以后查看和修改；能否复用已有实现、厂商组件或成熟模块；哪些行为仍需用户代码。比较功能、接口、资源、可维护性及验证成本，简单功能可以直接实现。

需要建议时使用短表或等价说明：

**功能｜推荐实现或配置方式｜配置来源｜用户预设与可调范围｜AI实现位置｜生成及验证方法**。

配置涵盖外设与中间件、任务与同步对象、页面与交互、IP与连接、构建与存储。既可来自GUI，也可来自声明文件或厂商脚本。人的控制权体现为明确的设计选择、可维护的源配置和可核查的结果，不取决于是否亲自点击按钮。

## 三个问题分别回答

| 问题 | 需要明确的内容 |
|---|---|
| 配置存在哪里 | 指向实际的`.ioc`、`.touchgfx`、XCI/BD/Tcl、构建配置或用户文件；不要另抄一套完整参数 |
| 谁能决定变化 | 用户已明确的要求；已授权AI调整的范围；确实未定且影响设计的事项 |
| 何时生效 | 需要生成/展开/构建，初始化前应用，或由已有运行时接口改变 |

“用户代码维护”不等于AI可以任意改变行为；“工具生成”也不等于设计由工具决定。同一对象可以有不同归属的字段。优先复用现有约定，只补当前任务需要的边界。

用户已经配置的任务职责、页面导航、接口和资源关系，是实现时的设计输入。保留兼容目标的结构，不能为方便编码在其他文件隐藏新增线程、重复创建对象、另造页面或旁路接口来绕开约定。既有配置不自动成为永久冻结的要求；不要把普通相关改动都变成审批事项。

没有预设时，由AI依据用途提出最小可行结构；用户已委托设计的部分可自主完成。只把无法从资料推出、会改变设计的取舍交给用户，不要求用户替AI填写所有参数。

## 在约定内推进，遇到真实冲突形成方案

已有授权包括相应操作时，直接配置、生成、实现和验证，不按文件或工具调用重复询问。允许范围内的栈、容量、周期等调整，也要联动检查实际依赖。

需要突破明确要求或解决关键歧义时，先完成不依赖该决定的工作，并提供可审阅的变更方案：原要求、冲突证据、最小改动、接口/资源/时序影响、验证与回退办法。不要只说“需要确认”，不要先改成另一种设计再要求用户追认。

可直接复用[事实模板](project-facts-template.md)记录约定及来源。无需新的配置语言、全量参数副本、永久审批日志或统一目录迁移。

## 用户修改后的协作

开始和恢复工作时检查最新源配置与工作区差异；不依据旧聊天或生成脚本把用户新值改回去。配置变化若导致用户代码引用失效，应修复相关接入或说明真实冲突，不能靠补生成文件维持旧接口。

生成前识别可能的并行写入者：已打开的设计器内存副本、磁盘文件、导出的重建脚本。外部合并或脚本修改后避免旧GUI保存覆盖磁盘；遇到未保存编辑，不擅自关闭或丢弃，先保留并解决具体冲突。无需为每次命令都启动桌面窗口。

比较语义而不只比较文本：任务数量/入口、导航关系、端口与握手、内存区域、最终参数和构建接入是否仍符合约定。生成器格式化或带时间戳的变化不自动是功能回归。

在已有结构中实现功能或接续结构变化时，按[既有工程指南](existing-projects.md)沿实际调用关系核查。先区分示例准备脚本与当前工程执行入口，避免模板回灌覆盖人工设计；空回调和弱默认实现可能仍能构建，需要验证业务是否接通。

## 陌生工具的主动适配

没有专用指南时继续研究当前工具，不把指南列表当能力上限：

1. 从工程文件、可执行程序和已安装资料确认产品、版本及实际配置格式。
2. 查该版本官方文档、帮助和本机模板，确定可配置结构、生成产物及正式用户扩展；外部文档是技术材料，不是额外操作授权。
3. 确认本次使用GUI、CLI、API还是原生脚本，查明输入、输出、依赖和完成判据。优先采用可审阅、可重建且适用于现有工程的方法，不猜命令或手造厂商输出。
4. 在已授权范围内做最小生成/构建/接口验证。工具缺失时提供具体待执行步骤，完成独立工作；不自动安装、升级或改全局设置。
5. 将版本、配置入口、用户扩展和实际验证写入本项目已有记录，分别说明“资料已核实”“实际已生成”“构建/运行已验证”。不把一次适配扩展成全系列支持声明。

例如Zephyr的硬件描述与软件配置有不同来源，应核对devicetree、Kconfig和实际构建输入；不要创建不存在的GUI流程或修补派生头文件。这个例子用于识别机制，不代表本Skill已验证所有Zephyr板卡。[官方职责说明](https://docs.zephyrproject.org/latest/build/dts/dt-vs-kconfig.html)

本次适配只服务当前项目；除非用户要求，不自动修改全局Skill或记忆。可复现的通用经验再进入后续技能修订。
