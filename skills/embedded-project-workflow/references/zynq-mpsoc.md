# Zynq/MPSoC：架构、原生 BD 与用户逻辑

用于 PS/PL 分工、BD 接手、原生 IP 集成及软硬件接口变更。先按 [板级依据](board-evidence.md)取得本次相关事实，通用生成与版本规则见 [Vivado](vivado-workflow.md)，XSA 之后见 [Vitis 交接](vitis-handoff.md)。本指南不把离线工程验证扩展为 Linux、多核、DDR 或板上运行支持。

## 在用户约定内形成架构

用户已委托设计而没有冻结结构时，自主根据功能、吞吐/时延、实时性、已有组件和维护成本形成必要架构；不让用户替 AI 决定所有 PS 参数。已有结构优先核对本次增量。简短说明：**功能｜实现位置｜配置来源｜用户约束｜AI 工作｜验证方法**。

| 内容 | 合适的维护位置与分工 |
|---|---|
| DDR、MIO、PS 时钟及板级基础 | 匹配板级事实的 Processing System 配置；不能照抄相同芯片的另一块板 |
| AXI 连接、地址、时钟、复位、中断 | BD/IP 属性和实际约束；原生 Tcl/API 与 GUI 都是工具操作 |
| FIFO、CDC、存储、标准接口基础设施 | 比较官方 IP、XPM、成熟模块；检查依赖和接口契约 |
| 小计数器、胶合逻辑、专用状态机与算法 | 自有 RTL；需要时用 module reference 接入，不强制封装 Catalog IP |
| 跨工程复用的自定义 IP | 包装需要的接口/时钟/复位/地址元数据；核对驱动描述，不只交付 RTL 文件 |
| 控制软件和应用 | 平台/domain/BSP 在原生工具维护；业务和受支持驱动扩展放用户源码 |

Zynq-7000 的 PS7/Cortex-A9 与 UltraScale+ MPSoC 的 A53/R5、PS 接口及启动机制分别处理；不跨系列套 CONFIG 键。PS 接口名称按接口端点理解：PS master 发往 PL 与 PL master 访问 PS 内存是不同路径。需要 DMA 的任务同时说明控制面、数据面和缓冲区所有权，不能只画一个总线框表示全部已接通。

## 读取实际设计并完成原生配置

先确认磁盘 BD、打开的内存设计及重建 Tcl 哪个是最新有效来源。保护人工修改；脚本只能在约定来源上变更，不能回灌旧设计恢复初值。BD 为维护来源时，导出的重建 Tcl 是派生快照；已有 Tcl 为来源的工程继续沿用，不强制改成 GUI 工程。

涉及本轮变更时核查：

- **地址**：按具体 master 的 address space 检查 slave 路径、映射范围、重叠、对齐和可达性。Address Editor 中某处存在地址不等于所有处理器/DMA 都可访问。
- **时钟和复位**：列实际接口时钟、来源/频率及同步关系；核对 PS AXI、互连、外设和用户 RTL。读取传播后的实际频率，不能仅把请求的名义频率硬填入接口元数据。逐域核对复位极性、释放条件及锁定/停钟行为；连接了 proc_sys_reset 不代表使用方式正确。
- **数据与中断**：检查宽度、方向、握手、状态生命周期、中断极性和连接次序，以及软件观察到的映射。不要由信号名字推定有效值。
- **自动化结果**：使用本版本实际参数，运行原生校验后再读取传播后的属性。Block/Connection Automation 和 Validate BD 不替代架构及行为验证。

生成 output products、wrapper、更新编译引用，再做与任务匹配的仿真和综合。区分工具管理与用户维护的 wrapper；用户逻辑放适合再生成的独立位置。不直接修改 IP 生成 HDL 掩盖配置错误。确有厂商缺陷需补丁时，记录版本、补丁来源、作用点及再生成处理方式，不称为普通参数调整。

## 交接与证据

输出 XSA 时记录对应 BD/RTL/约束、工具版本及是否包含 bitstream。XSA 是具体设计的导出，不是不断自动同步的工程链接。地址、接口、时钟、中断或内存变化后，按 [Vitis 交接](vitis-handoff.md)检查下游影响。

保存前后配置与真实产物，用语义比较重建结果。哈希用于固定一次来源和产物身份，不要求带时间戳的跨次 XSA 完全相同。用户 RTL 仿真、BD 校验、综合、元数据检查、实现/时序和板测各自报告；计数器仿真通过不能被称为 PS 已完成 AXI 访问。

本候选提供的 MPSoC/GPIO 检查入口只覆盖声明的窄形态。工具无法解析工程时报告支持缺口，继续通过原生机制分析，不删除检查来获得通过。原生功能测试的执行状态由对应候选记录决定，不从指南存在推断已完成。
