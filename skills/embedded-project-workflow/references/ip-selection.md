# FPGA 模块：复用、配置或自研

用于新功能选型、已有模块不适用或自写基础模块持续失败的任务。已定位的小修复直接处理，不先给整套架构选型。默认目标为可靠交付；用户明确要求学习、自研、跨厂商移植或其他约束时优先遵循。

选型服从当前[用户设计约定](configuration-contracts.md)。推荐成熟实现时也要保留约定的接口、时延、复位及资源关系，不能以“复用优先”为由静默改变它们；可行的适配在授权范围内实施，真正冲突则形成具体方案。

## 先找已有依据

读取足以决定本轮方案的顶层、相关RTL、IP配置/约束、接口说明和成功记录。先确定数据含义、生产/消费节拍、吞吐与时延、时钟域、复位和停机行为。已有资料能回答的事项不再追问；不知道真实需求时，不让用户先填FIFO深度或所有IP参数。

优先保留满足新需求的已验证模块。对于候选，区分“仓库有这个名字”“综合可用”“满足本工程接口”“已有运行证据”。只有缺口会影响选择时，才继续查资料或问用户。

## 按需求比较实现来源

| 场景 | 默认方向 | 必须留意的代价 |
|---|---|---|
| 已有模块满足需求 | 复用，检查增量 | 新速率、复位或时钟关系可能超出已验证范围 |
| 时钟、异步FIFO、复杂CDC、存储及标准接口基础设施 | 先评估厂商IP/XPM和已有实现 | 参数、器件/版本、接口延迟和约束仍需核对 |
| 简单计数、寄存器、专用小状态机、胶合逻辑 | 直接写必要RTL | 不为几十行简单逻辑引入额外IP/BD依赖 |
| RAM/ROM等常见资源 | 比较工具支持的推断模板、XPM和Catalog IP | 推断结果、读写冲突行为和时延不能靠代码外观保证 |
| 厂商功能、移植或许可不适合 | 比较开源模块和自研 | 源序、依赖、维护状态、模块契约与验证成本 |
| 明确的教学或自研目标 | 支持自写，限定功能并安排相应验证 | 成熟实现可作对照，不能以默认交付优先否定目标 |

XPM是厂商参数化模块。用户RTL中实例化XPM并不等于自行实现跨域指针、存储或同步器，也不需要一律封装成Catalog IP。反之，导入一个开源RTL文件也不代表它已经适用于当前器件和复位方式。

对当前有实质影响的项目做比较：功能与边界、吞吐/时延、资源、时钟复位、器件/工具支持、许可、依赖、仿真模型或已有测试。不要把每项变成必填访谈或凭来源名称声称故障率更低。

## 几个会改变选择的接口差异

- 单比特稳定电平、事件脉冲、相关数据总线和连续流不能用同一种CDC方式。逐位双触发器不能保证多位数据一致；按事件速率、允许丢失与反压要求选择同步器、握手或FIFO。检查停钟、源/目的复位及重新启动的契约。
- FIFO深度由突发、速率差和消费停顿推导；任何有限深度都不能无限吸收持续的平均速率差。检查满空、读延迟/FWFT、有效数据、反压、复位忙和实际接受的传输。
- 时钟选择考虑原生时钟资源、频率/抖动需求、合法输入与器件限制；简单低速事件通常可用clock enable。不要默认在普通逻辑中生成新的工作时钟。
- 接口转换和小型专用控制通常留在自有wrapper，避免修改厂商/第三方核心。wrapper必须兑现数据宽度、延迟、握手和复位假设。
- 开源模块的源文件说明、manifest和测试可能比仓库首页更具体。检查实际用到的文件许可、提交及弃用/替代说明，不自动升级或换库；未找到许可不等于获准复制。

## 如何向用户提出建议

用一两句话或短表说明选择，不要求另建文档：

**功能｜推荐实现/IP｜配置位置｜关键参数｜选择原因｜接入与验证**。

用户只需要决定无法从材料推断的用途和取舍，AI负责从这些要求推导关键配置。默认由用户进行图形配置；明确要求代操作后优先使用可审阅的原生Tcl或可用GUI。配置与生成规则见[Vivado工作流](vivado-workflow.md)。

若自写模块持续出现协议、CDC或边界问题且没有新增鉴别信息，停止无信息的局部补丁循环，比较复用/替换与继续自研。说明替换对端口、周期延迟、资源、许可证和回归测试的影响，保留可回退基线；无需为每个文件增加审批。

## 接入后的证据

复用降低的是重复实现工作，不消除集成错误。验证实际接受/输出的数据、复位、边界和相应约束；不以实例化成功、模板存在或OOC综合通过作为功能正确的证据。详细来源见[来源说明](sources.md)。
