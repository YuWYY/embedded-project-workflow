# 多阶段工程与中断续接

仅用于跨阶段、跨对话或需要交接的任务。小修改直接完成，不强制建立项目管理文件。Skill提供执行规范，不自行创建后台服务，也不保证工具或会话永久运行。

## 按结果拆分工作

先明确目标、可修改范围、工具代操作授权及交付终点；读取已知事实，不重复确认已有决定。需要设计取舍时按[用户设计约定](configuration-contracts.md)处理。

将任务拆成有依赖的可观察结果，例如基础配置能生成构建、关键功能链可验证、完整功能接入、约定验收完成。每阶段保留足以回退的版本及实际证据，不以文件数、代码量或文档完成率代替进展。

每个阶段按需要进行：读取当前配置与约定→实施源配置或用户代码→真实生成/构建→检查接口和有效参数→记录结果。范围内自主推进，不在每个阶段人为增加审批；需要等待外部决定时继续不依赖该决定的工作。

## 最少状态记录

优先更新已有项目说明；缺失时采用[事实模板](project-facts-template.md)。只保留：

- 目标、当前阶段和对应验收条件。
- 用户设计约定、已授权调整范围及待决事项。
- 实际配置、代码、构建入口和工具版本的位置。
- 最近成功源码身份及对应生成/构建/仿真或板测证据。
- 当前改动、失败或未完成项、下一步及需要的条件。

参数仍由原生配置维护，记录说明来源与理由。只在阶段完成、重要决定或交接时更新，不每轮复制长报告；不要另建任务数据库或强制JSON协议。

## 恢复时核对真实状态

先检查当前目录、分支/提交和未提交改动，再核对源配置及证据身份。不能假设记得另一对话，也不能用旧PASS证明更新后的源文件；状态记录有误时按当前证据修正，并保留未完成事实。

保护用户在中断期间的改动。查看是否仍有生成/构建进程写入该目录，结合实际进程状态和产物判定是否继续等待、恢复或重试；不因为存在锁文件就杀进程，也不盲目重复启动同一生成器。用户打开的工具或其他工程进程不属于本任务可随意清理的对象。

从最后未完成且依赖已满足的动作继续，不重做整个需求访谈或无变化的全量测试。需要复验时说明当前差异为何使旧证据不足。

## 失败与变更

配置已修改但生成失败时，明确标注“新配置未完成生成”，旧输出不能冒充新结果。保留日志、阶段和必要差异，先区分环境、配置、接口、应用实现及检查器错误，再决定重试、回退或更换方案。

没有新增鉴别信息的重复修补应触发方案重审；不为通过验收静默扩大用户限值、取消约束或修改验收标准。用户更改需求时更新对应约定、依赖和验证，而不是把以前成功结果沿用为新结果。

交付按用户目标逐项说明实际完成的层级和未覆盖部分，提供可重建入口、配置来源和必要依赖。构建、仿真与实机证据分别报告；未获得的结果保持未验证。
