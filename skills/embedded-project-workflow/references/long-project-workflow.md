# 多阶段工程与中断续接

用于跨阶段、跨对话或交接任务。小修改不强制新建管理文件；Skill不创建后台服务，也不保证会话或工具持续运行。

## 最少状态与任务身份

按可观察结果拆分工作，如配置可生成、关键功能接通、相关验收完成。授权与约定按[配置指南](configuration-contracts.md)处理，不在每阶段增加批准。

优先更新已有项目记录，缺失时用[事实模板](project-facts-template.md)。仅在阶段完成、重要决定或交接时保留：

- 目标、当前阶段和验收终点。
- 当前工程根目录、真实入口和工具版本；分支/提交及未提交改动。
- 用户约定、已授权范围、待决事实。
- 最近成功的源码身份、结果层级和证据位置。
- 当前差异、失败或未完成项，下一步及其条件。

配置值仍由原生文件维护，不另建全量参数副本或任务数据库。多人/多代理共用记录时由一个协调者维护汇总，各执行者只更新分配给自己的材料或返回观察，避免互相覆盖。

同名副本分别绑定实际根目录与入口，不以任务标题、目录最新时间或共享默认指针替代身份。明确选择的副本不存在或不匹配时，不静默回退到另一个；先报告具体差异，独立工作可继续。

## 恢复时核对磁盘

先核对当前目录、配置与旧证据身份；有Git时按需核对版本和相关差异，同轮未变的信息复用已有结果，无Git工程直接按文件身份接续。状态记录与实际来源冲突时，以核实后的当前状态修正记录，保留此前失败；旧PASS不证明修改后源码通过。

判断是否仍有本轮生成/构建进程在写入。锁文件存在不等于进程仍活着，也不授权杀进程；不要重复启动同一生成器。用户打开的设计器、未保存编辑和其他工程进程不属于可随意清理的对象。

从最后未完成且依赖已满足的动作继续，不重做访谈或无变化的全量测试。若需复验，指出哪些差异使旧结果不足。用户中断期间新增、重命名或删除对象时，按[结构接续](existing-projects.md)保留当前设计；新接口只有空实现时仍列为未完成。

## 失败与执行记录

配置已改但生成失败，要保留“新配置未完成生成”；旧产物不能充作新结果。区分环境、配置、接口、应用和检查器问题，再决定重试或回退。重复动作应带来新的鉴别信息，不静默扩大限值或修改验收标准。

长工具执行前记录本轮来源与阶段，输出直接进入本次日志；记录实际退出码、失败阶段、超时及清理结果。未启动进程时退出码为空。超时/受控中断只清理当前执行持有的存活进程树，不按名称结束软件，不把脚本退出码当厂商退出码。

运行记录采用同目录临时文件与原子替换；首次记录失败不启动工具，末次写入失败报告未确认。启动异常、强制结束或存储故障可能留下RUNNING；恢复时结合真实进程、当前源码、产物和终态判断，不能将其视作成功或自动重跑。成功标记仅在验收与结果保存后推进。这里是执行器要求，普通编辑不必新建记录系统。

## 检验是否能接着做

交接者应能指出本轮目标、准确工程入口、用户新改动、最近证据对应的源码，以及下一个未完成动作。必要时用新上下文做一次只读接手，发现遗漏再修补记录，不靠摘要长度或文件数判断恢复质量。

交付按目标说明实际结果与未覆盖部分。代理预验、真人维护反馈、工具结果和板测各自记录；真人未参与保持未执行，不伪造完成，也不阻塞已授权的独立验证。
