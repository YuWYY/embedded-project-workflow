# 可公开的继续工作记录

更新日期：2026-09-28。当前配置为输入 50 MHz、输出 125 MHz。项目约定见 `PROJECT.md`，唯一设计配置源是 `config/clock-config.tcl`。

## 已完成的阶段

- 旧配置 100 MHz：IP 生成、XSim 和 IP/顶层综合通过；400 周期、两轮复位、10 ns。
- 用户仅修改配置源至 125 MHz 后，历史成功结果仍只证明旧值；交接时当前配置尚未验证。
- 新的独立 CLI 会话依据约定、状态、当前源码和历史证据识别差异，完成 125 MHz 再生成以及全新目录构建；两者均为 400 周期、两轮复位、8 ns，IP/顶层综合通过。
- 私有原工程的端口、三阶段复位、用户 RTL、TB、约束与执行脚本均保持不变，100 MHz 阶段证据哈希保持不变。
- 公开整理后复用现有共享源，移除私有安装路径，另以公开入口追加一次全新目录 clean125。公开入口和历史入口的实际结果与哈希分别记录在 `validation-20260928.json`。
- 独立复核增加了所属标记、成功阶段核验和当前频率/周期结果匹配。旧结果会在执行前清理，普通工程或无匹配证据的目录不会被接管。
- 同频率再生成出现有效 IP 缓存完成状态未被原检查器覆盖的情况；为明确验证实际 OOC 重综合，最终 Tcl 仅在当前试验项目禁用 IP 缓存，未修改共享缓存或全局配置。
- 最终公开入口的全新 clean125 通过：105.53 秒、400 周期、两轮复位、8 ns，并完成 IP/顶层综合。同目录再生成在 XSim 设置阶段无法读取 `xsim.ini`，一次同源码重试触发 `Tcl_Close` 通道引用计数异常和 `EXCEPTION_BREAKPOINT`；两个失败记录保留，之后没有继续调用。退出后文件可读取，根因未定。

## 当前阻塞

最终公开入口的再生成验收尚未闭合，暂不把本例记为整体通过。历史 100→125 续接和旧入口再生成成功有各自哈希；不能覆盖当前失败。进一步工作应依据保留的错误和崩溃产物分析工具读取问题，不能继续没有鉴别信息的重试。失败阶段中残留的综合报告来自先前 clean；没有本轮完成标记或仿真 PASS。

## 可恢复事实

不得直接复用别人机器上的临时目录；原始工具产物没有放入公开包。使用 `scripts/run_clock.py` 和新的 ASCII 构建根目录重建。复现 100→125 时先建立自己的 100 MHz 成功基线，再修改唯一配置源，使用新阶段名再生成，最后从空目录复验。

XCI、配置副本与报告只是证据，不作为新的配置来源。成功状态必须同时匹配当前配置和源码哈希；修改配置后将相关旧结论标为待复验。

## 仍未覆盖

布局布线、bitstream、下载、板测、实现后时序收敛、板级 `reset/reset_out` 外部延迟，以及额外停钟/失锁、抖动、温压和硬件亚稳态验证均未完成。当前目标不包含这些工作。

这是一项有边界的续接观察，不能证明任意长项目都能可靠恢复，亦不能量化额度节省或故障率变化。
