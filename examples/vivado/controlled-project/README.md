# Vivado 受控配置与任务续接

本示例展示用户预先确定接口、复位和允许修改的参数后，AI 如何根据配置和阶段证据继续完成工作。它复用上级 `sources` 中的时钟 RTL、测试平台和 XDC，不引入新构建框架。原创文件采用仓库根 MIT；AMD 工具和生成 IP 为外部依赖，不随本目录发布。

请连同整个 `examples/vivado` 目录使用；单独移动 `controlled-project` 会失去共享源文件。运行需要 Windows、Python 3.10+、Vivado 2025.1、对应 Artix-7 器件支持及 Clocking Wizard 6.0。

## 先看约定与证据

[PROJECT.md](PROJECT.md) 记录用户约定；`config/clock-config.tcl` 是唯一配置源，交付值为输入 50 MHz、输出 125 MHz。共享 `clock_top` 保留五个端口和三阶段复位适配。

真实续接案例先完成 100 MHz，随后仅把配置源改为 125 MHz。新的独立 CLI 会话没有前序对话，仅依据项目约定、继续工作记录、源码和历史证据恢复任务。它识别出历史 100 MHz 的 PASS 尚不能证明当前 125 MHz，实际完成再生成和新的空目录构建，保留原接口、复位检查与旧证据。

[STATE.md](STATE.md) 是脱敏后的继续工作记录；[validation-20260928.json](validation-20260928.json) 区分历史工具入口、公开入口和相应源码身份。一次案例观察不构成效率或可靠性的统计证明。

## 重建和再生成

在本目录运行，替换占位符为已有工具和新的 ASCII 路径：

```powershell
python -B scripts/run_clock.py --vivado "<Vivado安装目录>/bin/vivado.bat" --stage clock125-clean --build-root "<新的ASCII构建目录>"
```

Windows PATH 中已有 `vivado.bat` 或 `vivado.exe` 时可省略 `--vivado`。构建目录须位于整个 Vivado 示例源码目录之外；首次构建拒绝非空目录。未指定路径时使用系统临时目录，如果临时目录含中文则会拒绝，应显式传入 ASCII 路径。默认临时目录选择可能留下未使用的空目录；入口不会清理其他目录。

复现 100→125 的步骤：

1. 在唯一配置源中将 `output_mhz` 设为 100，用新目录和 `--stage clock100` 运行。
2. 仅将 `output_mhz` 改为 125，沿用该构建根目录并增加 `--regenerate --stage clock125-regenerate`。
3. 再选择全新的 ASCII 目录，不带 `--regenerate`，运行 `--stage clock125-clean`。

入口把本次配置、三个共享时钟源文件和脚本复制到隔离目录，实际调用 Vivado batch。每次保留独立 `stage-results/<阶段名>`；阶段名只使用 ASCII 字母、数字、下划线和连字符，不允许重用同名阶段。入口不修改共享源文件，也不调用实现或硬件操作。

新目录写入本例格式/version及唯一身份的所属标记。`--regenerate` 在复制或清理任何文件之前，核对该标记、匹配的成功阶段、阶段配置快照及本例工程；普通 Vivado 工程、错误标记或缺少成功证据都会拒绝。没有这一标记的旧版本构建不会自动接管，应从新目录重建。

每次实际执行前将10个固定旧证据文件归档至当前阶段的 `preexisting-artifacts`，保留原字节与相对路径；当前阶段只采集重新产生的文件。普通用户报告和旧成功阶段保留。成功判定要求本轮的完成频率、仿真期望周期与唯一配置源一致，不接受旧频率的 PASS。所属标记与阶段证据用于识别该构建，不是新的设计配置来源。

首次写入前检查每个实际复制和证据目标，并检查本例所属树；指向根目录外的链接会拒绝，不跟随外部目录。源脚本或配置删除/改名后，应从新根重建，避免旧副本残留造成inventory不一致。

## 覆盖与局限

v0.3候选增加 `--timeout`（默认每个子进程900秒）、提前保存的阶段记录、Popen日志流和仅针对本轮存活PID树的超时/中断清理。实际退出码在启动前为空；清理与保存失败不能被成功退出掩盖。结果原子替换并核对后才更新成功所属记录。上文11方法与四阶段原生结果是v0.2历史证据，本候选的主机故障回归及原生结果见完整仓库的 `docs/validation-v03.md`（该记录位于独立示例ZIP之外）。

周期检查为每次复位后 200 个输出周期，共 400 个周期、两轮复位；125 MHz 对应 8 ns，保留异步置位、锁定和同步释放检查。源哈希、实际 IP 参数、编译引用和综合报告分别核对。

没有进行布局布线、bitstream、下载、GUI 调试或板测；综合时序报告不能证明实现后时序收敛。`reset/reset_out` 的板级外部延迟未指定，输入停钟、失锁故障注入、抖动、温压和硬件亚稳态仍未覆盖。固定器件、时钟范围和复位次数仅为本例测试条件。

已知日志包含重复但同值的 50 MHz 输入时钟定义、`glbl` 未声明测试平台参数、标准综合回退等提示；旧工程再生成还出现无关板卡目录提示。保留具体解释，不以添加宽泛例外消除警告。原始日志、XCI 和 DCP 可能含本机路径且属于生成产物，留在本地构建目录，不直接公开上传。
