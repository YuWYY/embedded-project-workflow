# 受控时钟项目约定

这是原创配置和用户 RTL 的最小协作示例。目标是在保留接口与复位契约的前提下，将 Clocking Wizard 输出从 100 MHz 调整到 125 MHz，并通过再生成和空目录重建验证。参数只用于本案例，不是 Skill 的默认值。

- 保留 `clock_top` 的 `clk_in`、`reset`、`clk_out`、`reset_out`、`locked` 端口及其语义。
- 保留三阶段复位适配：`reset` 或失锁异步置位，在输出时钟域同步释放；不能删除复位检查来取得通过。
- 输入固定 50 MHz；允许调整输出 100–125 MHz，接口保持不变。
- 试验组合固定 Vivado 2025.1、Clocking Wizard 6.0、`xc7a200tfbg484-2`；不升级工具或替换器件。
- 唯一设计配置源是 `config/clock-config.tcl`；XCI、构建副本和报告都是派生产物，不成为第二套可编辑配置。
- 用户层复用上级目录 `../sources/clock_top.sv`；独立测试平台为 `../sources/tb_clock.sv`，输入约束为 `../sources/clock.xdc`。本目录不复制第二套 RTL。
- 在已有任务授权内，可编辑配置、运行 batch 生成、XSim 和综合。新需求涉及端口、复位、用户层或实现范围时，应先说明具体影响，并按项目实际授权处理。
- 验收覆盖 IP 生成、XSim、IP/顶层综合及证据身份核对；不包含实现、板级时序收敛、bitstream、硬件连接、下载、调试器或板测。

入口为 `scripts/run_clock.py`，使用新的 ASCII 构建目录和新的 ASCII 阶段名。已有构建仅在明确 `--regenerate` 且本例所属标记、成功阶段证据核对一致时复用；普通工程或无标记旧构建不自动接管，既有同名阶段证据拒绝覆盖。所属标记不替代设计配置源。未取得当前配置证据时，历史 PASS 只能证明当时的配置。
