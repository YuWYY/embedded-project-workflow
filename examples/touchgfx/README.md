# TouchGFX：用户预设结构与 AI 用户层接入

本原创合成案例使用本机 TouchGFX 4.26.1 的 PC Simulator 包。用户预先规定两个页面、导航、控件名称和布局，AI 只在用户 Model、Presenter、View 实现动态计数与暂停状态。

`ui-before.json` 和 `ui-after.json` 是 `.touchgfx` 的 Screens 配置片段。重建入口先用厂商本地模板创建工程，再将片段写入源配置并调用真实生成器，不手写生成基类。后一个片段模拟用户将 `counterValue` 改名 `sampleValue` 并移动到 `(40,80)`。

数值每 60 个 GUI tick 增加 1，最大 999999；暂停保留已累计的部分周期。此处是确定性的演示计数，不能当成实际经过时间或传感器数值。页面切换保留 Model 状态，Presenter 激活时读取当前值，后续通过 ModelListener 更新。

## 重建

在 Windows 上提供已安装的 TouchGFX 4.26.1 根目录，以及包外的全新空构建目录：

```powershell
python -B rebuild.py --touchgfx-root '<TouchGFX安装根目录>' --build-root '<全新空构建目录>'
```

依赖 Python 3、安装中自带的 `designer/tgfx.exe`、两个本地 TPA 包、MinGW GCC/Make、TouchGFX 框架及默认 Verdana 字体。脚本不安装或下载依赖，不启动 GUI，不构建或烧录目标板。TEMP/TMP 只在子进程环境中指向构建目录；不会改变系统设置。

过程实际创建并生成原始设计，接入用户代码，构建模拟器；再应用用户的名称/布局变化并生成，验证用户文件保留。旧引用应当导致一次真实构建失败，随后仅调整用户 View 引用并重新构建；最后再次生成检查保留，并用实际 Model.cpp 运行独立业务测试及受控输入错误负例。

`user` 中的代码是最终适配版本。首次构建由脚本将其中 Dashboard 控件引用映射到初始设计名称，随后恢复最终适配；不会以恢复旧 `.touchgfx` 或修改生成文件绕过用户修改。

## 证据范围

`results.json` 与完整日志保存在构建目录。模型测试使用真实业务源码和独立预期，未替代 TouchGFX 的 Unicode 或图形库。它验证业务状态；原生模拟器构建验证实际库及生成接口可以编译链接。脚本没有启动模拟器或点击界面，所以没有视觉、导航交互或板上性能的运行结论。

生成树中会出现厂商框架、库、字体、模板及生成产物，均沿用原许可，仅留在本机构建目录。此源码包不包含这些内容；原创配置片段、业务实现、测试和脚本采用仓库的 MIT 许可，署名 YuWYY。不要将构建目录整体加入公共仓库。
