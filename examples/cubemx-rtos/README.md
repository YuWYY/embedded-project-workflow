# CubeMX / FreeRTOS 配置所有权小工程

本示例用于验证：用户从 `.ioc` 规定任务与队列，CubeMX 生成对象框架，独立 APP 文件实现行为，再生成后配置变化和应用接入能够保留。测试芯片是 STM32G474RET6；这不是 Skill 的默认芯片、任务数、栈大小或调度方案。

原创部分采用 MIT，Copyright (c) 2026 YuWYY。源码包含原创 `.ioc`、APP 文件和 Python 重建脚本；STM32CubeMX、固件包、CMSIS/FreeRTOS、ARMCC 和器件包均为外部依赖，不随本示例复制发布。

## 工具与运行

本轮测试组合：Windows、Python 3、STM32CubeMX 6.18.1、STM32Cube_FW_G4_V1.6.3、ARMCC 5.06 update 7 build 960、Keil STM32G4xx_DFP 2.0.0。其他版本需要单独核对，不保证生成内容完全相同。

在本目录执行，参数替换为本机已有工具和新的空构建目录：

```text
python -B rebuild.py --cubemx "<STM32CubeMX.exe>" --firmware "<STM32Cube_FW_G4_V1.6.3目录>" --uv4 "<UV4.exe>" --build-root "<新的空构建目录>"
```

`--reports` 可另指定日志目录。缺省日志在构建目录的 `reports` 中。构建根目录和报告目录都必须不存在或为空，且均须位于本示例原始源码目录之外；这些检查在建立输出目录和调用厂商工具之前完成。脚本不清理或覆盖既有工程、报告；临时目录仅设置到子进程环境。它调用 CubeMX 原生命令和 Keil Rebuild，不下载依赖、不安装软件、不启动下载、调试器、串口或硬件。

v0.3候选的 `--timeout` 为每个子进程的等待上限，默认360秒。运行记录在复制与执行前建立，阶段失败、超时和受控中断保留日志、真实退出码及本轮PID清理结果。失败不会将未执行阶段标成成功；持续写盘故障时记录可能未完成，应按当前来源和实际产物恢复判断。

已有工程按名称修改栈与队列的窄适配器随Skill包提供，见 [支持矩阵与试用](../../docs/validation-v03.md)；固定示例重建与既有工程适配分别验收，不将同一个案例通过扩大为任意工程兼容。

生成文件、固件和原始工具日志只位于指定输出位置。原始 Keil 日志可能含本机注册信息，不要直接公开。仓库发布应只收录本示例源文件和脱敏结果。

## 测试流程与分工

| 项目 | 配置/实现来源 |
|---|---|
| 芯片、HSI、HAL 时基 TIM6、CMSIS-RTOS2 与 NVIC | `.ioc` |
| 两个任务、优先级、栈深和分配属性 | `.ioc` 的任务配置 |
| 队列类型、容量和静态内存 | `.ioc` 的队列配置 |
| 生产者/消费者循环与创建失败检查 | 独立 `APP` 文件 |
| 用户实现接入生成框架 | 真实 USER CODE Includes / RTOS_THREADS 区域 |
| 工具链版本与 APP 编译引用 | Keil 项目元数据；再生成后检查保留 |

初始静态变体由两个正常优先级任务和一个 8 元素的 `uint32_t` 队列组成。Producer 栈是 256 words，即当前 Cortex-M4 目标的 1024 bytes。模拟用户修改仅编辑配置源，将 Producer 栈改为 384 words、队列改为 16 元素，然后实际再生成及构建。

第二个变体仅将 Producer 改为动态分配；Consumer 和队列仍为静态。该例演示逐对象选择，并不推荐所有工程统一使用同一种分配方式。两个版本均保留当前 CMSIS 封装所需的静态/动态支持宏；本例不声称整个固件没有堆。

应用在任务中传输递增整数，并保留计数器供后续运行时观测。当前交付只验证生成、目标构建、符号接入和配置保留；未运行该应用，计数器与顺序检查没有获得板测证据。

## 实际工具边界

当前 CubeMX 模板即使把第一个任务设置为 `As external`，仍生成一个弱默认任务体；第二个任务按 external 处理。脚本保留厂商行为，通过 MAP 核对两个实际入口都来自用户对象文件。不能只看 GUI 标签就断言漏实现一定链接失败。

负例在独立副本中移除第二个 Consumer 的用户实现，必须因 `Consumer_Entry` 未定义而链接失败。负例构建失败是预期结果，不作为可用固件。

CMSIS `stack_size` 是字节，本机 CubeMX 任务表是 words；静态数组通过 `sizeof` 传给 CMSIS，动态配置通过 words × 4。C 语言 `static` 关键字、RTOS 对象分配策略以及对象的创建时机是三个不同概念。

本轮未改变或替换厂商 CMSIS 中间件。对“无堆”要求，应另查实际版本中的事件、软件定时器回调包装、服务任务和其他依赖；当前 G4 包的 `osTimerNew` 即使提供静态 TCB 也会为包装结构分配内存。

## 证据边界

重建脚本检查实际输出和错误日志、唯一对象创建、栈单位、队列容量、编译引用、APP 哈希保留及 MAP 符号。它还验证缺失 external 实现的链接负例。

不包含板上启动、调度、时延、栈水位、堆峰值或通信功能验证；编译和链接通过不能替代这些测试。任务数、优先级、周期、栈大小和队列容量均为合成案例值。
