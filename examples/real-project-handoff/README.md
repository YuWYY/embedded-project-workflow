# 真实已有工程接续：运行状态页

本例提供原创纯 C 业务模块和独立预期契约。第三方完整工程、生成树和包含上游代码的差分不随包分发。它不是任意 CubeMX 工程的自动修改器。

## 输入与维护边界

本地验证采用 [OPEN-MCU-UI 固定提交](https://github.com/arona-jkb/OPEN-MCU-UI/tree/2c08e5dfd7ddc237dfd61440dfc9d45705c19e1d)，STM32F103C8T6、裸机主循环、已有 Custom Screen 2、CMake Debug。取得源代码后先检查其构建定义、依赖、许可和输出位置；不要直接执行仓库里的其他脚本。

源码中的 SPI/DMA 设置与 README 的 I2C 概述存在差异。本例按实际源码构建，未调整显示接口，也未据此确认目标板接线。原链接区仍为 Flash 64 KiB、RAM 20 KiB。

| 内容 | 有效来源 | 接入位置 |
|---|---|---|
| 芯片、时钟、引脚、外设 | 原 IOC 与其生成基础 | 本次业务接入沿用 |
| 状态刷新周期和菜单名 | `status/status_config.h` | 用户维护，不要求 CubeMX 再生成 |
| 时间和循环统计 | `status/epw_status.c` | 独立用户模块，加入顶层 CMake |
| 页面绘制与主循环调用 | 原工程的受保护用户区 | 沿用 Custom Screen 2 与现有 UI 回调 |

## 业务契约

进入主循环前，以当前毫秒 tick 初始化状态；每轮调用一次 `epw_status_poll`，即使显示的是其他页面。读取 `visible` 绘制累计秒数和循环数。示例刷新周期为 100 ms，续接材料使用 250 ms，它们都不是 Skill 的通用默认值。

累计时间来自实际经过的毫秒数，与快照刷新次数分开。迟到时只发布一次；刷新不新增阻塞延时，也不替代原来的 UI 渲染循环。无符号 tick 差支持回绕，前提是连续两次调用间隔小于一个完整 32 位毫秒周期；循环数按 32 位回绕，公开秒数在 `UINT32_MAX` 秒后回绕。

## 无厂商 SDK 的主机验证

从仓库根目录运行，替换编译器和输出目录为本机路径。输出目录必须尚不存在：

```text
python examples/real-project-handoff/tests/check.py --cc <现有主机gcc路径> --output <新的测试输出目录>
```

检查实际 `epw_status.c`，覆盖初始值、刷新边界、迟到、tick 边界及完整周期、循环计数回绕和 250 ms 参数。受控负例分别将时间固定、用刷新次数代替真实时间、硬编码回 100 ms、把累计毫秒截断为 32 位；负例必须在预期断言失败，编译失败不计为检查器成功。

## 目标工程接入与重建

1. 将本例 `status` 中的原创模块置于独立用户目录，由顶层 `CMakeLists.txt` 添加源文件与头文件路径。
2. 在 `main.c` 的正式用户区域初始化与调用模块。初始化放在进入主循环前；主循环保留原有动画、按键和 UI 调用。
3. 在已有 Custom Screen 2 的用户绘制回调读取快照。菜单名称引用用户配置；不替换导航系统。
4. 使用项目的 Debug preset 配置并构建。编译器使用原 ARM GCC 工具链，检查实际 ELF、MAP、编译输入及反汇编调用，不能仅检查文件存在。

```text
cmake --preset Debug
cmake --build --preset Debug --parallel 4
```

先将已有 ARM GCC 和 Ninja 的目录加入本次进程的 PATH。不要修改系统环境变量来完成本例。本轮使用 GCC 13.3.1、CMake 3.28.1、Ninja 1.13.0 的已安装环境。

独立兼容副本才执行 CubeMX 6.18.1 / F1 固件 1.8.6 的转换与再生成；原工程声明的 6.15.0 本轮未运行。生成前保留 IOC、用户文件和源清单，生成后核对实际差异，分别执行构建、再次生成和空构建目录重建。
