## 公开工程与真实构建

上游固定为 [OPEN-MCU-UI / 2c08e5d](https://github.com/arona-jkb/OPEN-MCU-UI/tree/2c08e5dfd7ddc237dfd61440dfc9d45705c19e1d)。先核查构建定义、依赖、输出和可能的自定义命令，再使用其原 Debug preset。保留完整输入与逐文件哈希；没有执行上游烧录、调试或其他辅助脚本。

原始构建 Flash 使用 51,228 / 65,536 字节，RAM 使用 6,640 / 20,480 字节。独立准备的状态模块基线及固定版本再生成后的构建为 Flash 52,328 / 65,536、RAM 6,680 / 20,480。未扩大链接区、换工具链或重构 UI 来取得通过。各代理独立实现的布局另随其实际产物记录，不套用上述字节数。

任务 A 的两个版本从相同上游输入分别实现 Custom Screen 2 的运行状态显示；任务 B 从另一份独立准备、已构建成功的模块基线接手 250 ms 和菜单名变化。B 的变化是明确标记的测试输入，不是真人编辑。两个实验均只提供原始材料与指定 Skill，不提供评分标准或另一组实现。

完整第三方工程、生成树、ELF、原始日志及含上游代码的差分留本地。公开部分只有[原创模块与契约](../examples/real-project-handoff/README.md)、固定来源、必要重建说明和脱敏结果。

## CubeMX 转换的适用边界

上游 IOC 声明 6.15.0；本轮通过真实原生 Migrate 对话框转换到 6.18.1。工具同时默认选择 F1 1.8.7，随后在配置源恢复固定的 1.8.6，禁用 LastFirmware，并用已安装的 1.8.6 目录生成；没有手改 MxCube/MxDb 版本来冒充迁移，也没有安装固件包。

旧 `.mxproject` 带 `../Core` 删除追踪。首次保留其原件，让工具在副本重建元数据；固定组合的两轮均保留新 `.mxproject`，并将源配置 `DeletePrevious=false` 明确作为迁移准备。它只防止本次沿袭的旧文件清理路径，不证明任意删外设场景仍无陈旧文件。

两轮检查用户区域、自有模块、顶层 CMake、主循环调用、链接区和实际 ELF/MAP。第二轮使用新的构建目录；引脚、时钟与外设等硬件键的比较、固件来源及生成差异另留本地记录。普通应用周期修改沿用现有生成基础，只有独立兼容副本执行上述迁移。

## 行为执行与真实失败

固定请求模型 `gpt-5.5`、medium，先完成真实写入/读回/结果持久化预检。环境为本轮进程配置，没有改全局设置；它不是操作系统级隔离虚拟机。

| 批次 | 结果 | 解释 |
|---|---|---|
| 原始 10 次 | 7 PASS / 3 FAIL | 首次概览漏 `words`；两版 A 在完整 tick 周期后累计秒数归零 |
| r1 定向两次 | 2 PASS | 只复测首次概览和不受窄执行器支持的工程分析 |
| r2 定向一次 | 1 PASS | 同一原始 A 输入重新接手，实际实现正确累计经过时间 |

原 A 两组的目标构建和自身宿主测试都通过，但独立复核每 1,000 ms 调用实际源码，累计到 4,294,968,000 ms 后发现秒数为 0，预期为 4,294,968。r2 的同一独立检查得到正确秒数和循环数。其执行代理自己的测试仍只覆盖近边界初始化；完整周期证据来自独立复核，不写成代理自测已经充分。

13 次均分别记录功能、配置保护、证据准确性和说明完整性；未发现保护范围内越权改写、重复索取已知信息或把未运行的板测称为通过。评分者未编写这些案例或执行代理答案，但参与了 intake 开发，不能称为外部盲测人员。

最终 r2 没有重新执行全部场景；只重测实际受到修订影响的项。工具调用、可观测输出字节、耗时与宿主 usage 保留原值：有些调用减少，有些读取量增加，r2 仍读了无关的 TouchGFX 指南。**不据此宣称统计提效、全面减少读取或保证不再出现同类错误。**
