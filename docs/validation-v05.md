## 实际问题及修订

| 发现 | 处理与保留的限制 |
|---|---|
| 100 MHz 请求与 module reference 时钟元数据不一致 | 板 preset 的 PS 参考为 33.330 MHz；Vivado 推导为 99,990,005 Hz。用户接口元数据匹配实际传播值，未擅改板级时钟依据；两者均非板上实测 |
| 原生 Tcl/IP scope 异常 | 保留每次首个错误与未执行阶段。隔离诊断与单线程后曾成功，但同类异常又出现，不能宣称线程数是已证实根因或问题已根治 |
| XSA 内含多个 HWH | 依据实际 hwdef 的 DEFAULT_BD/SCOPED_BD 选择顶层并检查成员；不以任意第一个 HWH 代替 |
| 读取或最终来源检查失败却缺少失败阶段 | 为对应读取、source_identity 和 persist_result 分别记录失败；保留此前已完成结果 |
| 超时处理时 launcher 已退出 | 记录子孙进程状态未确认，不将未执行清理写为完整；只处理持有的本轮进程 |
| native 最终记录写入失败 | 汇总阶段记为 UNCONFIRMED，保留已观察 PID/实际退出码；不回写为未启动 |
| XPR 外部 Run Dir、IPOutputRepo 或工具安装目录输出 | 执行前明确拒绝；合法内部 $PCACHEDIR 路径有正例，未以关闭检查恢复通过 |
| 仿真负例只匹配通用断言文字 | 改为清零或暂停的具体断言原因；超时和编译错误不算业务负例通过 |
| 工具退出零但 XSA/DTS 为空仍通过 | 检查 XSA ZIP/CRC、声明顶层 HWH 及 SDT 引用文件完整性；空、缺失、ZIP 损坏或越界引用均拒绝，失败阶段保留。此门禁不解析完整 DTS 语法，节点及交接语义须另由独立检查器验证 |
| 未分配 GPIO 地址仍被原生 validate 接受 | 实际告警与零退出保留；不把脚本后备报错称为原生拒绝，另用地址重叠核验冲突 |
| 地址重叠负例 | 隔离副本增加第二外设，原生 assign 以 BD 41-1075 拒绝同范围重叠，实际退出 1；正常工程仍只有一个 GPIO |
| 真人接续时将生成 wrapper 当用户代码保护 | B 的生成/综合/XSA 与 SDT 原生阶段均退出 0；旧入口因 wrapper 日期注释变化失败。修复只单列精确工具管理路径，用户 RTL/XDC 及引用仍保持保护。原 FAIL 保留，针对真实 B 前后文件的修复后校验通过；未冒充又做了一次 B 原生构建 |
| 空目录重建时 Windows batch 拆分逗号连接的 BD 名称 | 改为每个 BD 独立参数，保留 C1 的实际失败 |
| C2 的原生 Tcl 读取异常及长路径告警 | 改用较短的专用 ASCII 输出，C3 原生阶段通过；路径与首次错误分别记录，不据此认定历史 Tcl 问题根因已解决 |
| 原生 ImportPath 被当作编译配置拒绝 | 仅将 ImportPath/ImportTime 视为导入来源信息；实际 FilePath 仍检查归属。显式宏、generic、包含配置、使用标志和额外源文件仍拒绝，不能悄悄漏掉用户编译设置 |
| 原生导入把 PS 的隐含参数写成显式字段 | 保留 `PSU_MIO_22_INPUT_TYPE=cmos` 的原始差异；必须用 B/C 完整有效 XCI 参数、HWH 参数/属性/地址映射以及 BD 连接关系核对，不能把目录默认值 NA 当作等价证明 |
| 后验读取器假定每份 XCI 都有 model_parameters | 实际 RTL module reference 无该容器；只对已确认的该形态接受缺少可选段，必须的 component_parameters 和厂商 IP 形态继续检查。第一次后验 FAIL 保留，新记录使用新名称 |

## 已完成的真人输入与交接检查

用户实际保存了 `0xA0010000` 地址，范围保持 64 KiB。新上下文代理先读取真实 BD 并报告结果，之后 root 对固定快照独立比较：主设计仅地址改变和校验标记失效，原始计数 RTL 字节未变。人工保存后的工程还多出一个空 `design_1.bd`；该文件被保留，实际顶层仍为 `system_wrapper`，空设计不参与顶层综合。

新代理未取得预制实现或评分答案；它先得到当前工程、约定、状态与 Skill，报告独立读取结果后，root 才给出快照差异的复核反馈。B 在新工作副本生成，原始人工工程保持不动。

[真实交接矩阵](../examples/vivado/soc-handoff/validation-handoff-20261002.json)记录了未修改厂商产物的组合：A/A/A 与 B/B/B 通过；B/A/A 按 STALE_BD_XSA 失败；B/B/A 按 STALE_XSA_SDT 失败。以旧 A 验证记录核对一致的 B 三源，也按 STALE_RECORD 拒绝。C 空目录重建的 BD/XSA/SDT 也通过，检查器提取的 GPIO 语义与 B 完全一致。这是元数据交接检查，未复现 BSP 或应用运行故障。

C 从当前保存的 BD、XPR 资源属性及原计数 RTL 创建空工程，未调用旧 `prepare.tcl`，未复用旧 wrapper、DCP、XSA 或 SDT。导入/生成、综合/导出、SDT 的实际退出码均为 0。旧入口在这些阶段完成后拒绝原生 ImportPath 元数据，原始记录仍为 FAIL；修订后验入口单独记录其源码身份，不倒改原执行记录或退出码，也不宣称最终入口全链又运行了一遍。

最终实际后验已退出 0：7 个 XCI 的完整 component/model 值、7 个 HWH 模块属性及 1782 项参数、内存映射与当前 BD 关系一致；原始 BD 唯一的 MIO22 显式化差异仍保留。真实旧 A XSA 配当前 B BD 的独立负例被拒绝，证明参数相同不能掩盖地址陈旧。这里的相等是已检查的配置语义相等，不是网表形式等价或板级证明。详见[接续与重建分层结果](../examples/vivado/soc-handoff/validation-continuation-20261002.json)及[使用步骤](../examples/vivado/soc-handoff/CURRENT_REBUILD.md)。

结束时重新核对：原始 v0.4 的 623 个文件、A 基线的 417 个文件均无新增、缺失或变化；真人工程清单中的 6 个输入与固定快照均未改变。对真人工程的保护结论限定为声明的输入清单，不扩大到所有 GUI 缓存。

## 证据身份与支持边界

各原生阶段记录实际运行入口和输入哈希。后续脚本修订后的主机回归不能反向改写早先原生运行的源码身份；重新执行的阶段另立记录。人工阶段、自动续接、BD/XSA/SDT 语义检查、RTL 仿真及软件构建分别报告。

A53 用户程序使用本机 GPIO SDT 驱动的基地址配置机制；没有制造 xparameters.h、BSP、ELF 或平台生成日志。SDT 生成不等于 Vitis 平台/BSP 构建，也不等于 Linux 最终设备树部署。

CubeMX、FreeRTOS、TouchGFX 与 ESP-IDF 本轮只复验受通用指南影响的行为案例；旧工具运行结果继续列作历史证据。未修改的 FIFO 不重复执行。远端 CI 未运行；本地测试、包校验及后续验收结果须分别记录。

完整生成树、原始日志和个人路径只保存在本地隔离输出。公开候选只收录原创源码、许可说明、可重建入口和脱敏结论。
