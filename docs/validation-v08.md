# v0.8 两张工程规划图验证

本轮为 **v0.8.0-beta.1 本地候选**，基线是已发布 v0.7 提交 `bbe108af8f07b0c561e0b51126fdc4d0ecc0f1e3`。首轮执行于 2026-10-04；中断后的收尾于 2026-10-08。未安装、自动启用、推送或发布。

## 交付与证据边界

主入口增加一条按需路由和一段交付规则；新增规划图指南、五份可编辑 SVG 及标准库画布/模板生成器。完整规划提供同一工程的引脚功能与执行逻辑两图。小修改和第一次只读概览保持原有范围，不要求画图。

SVG是可编辑说明，原生配置仍是参数来源。PNG只使用已有渲染环境和字体。没有新增工程JSON、自动布局器、全局任务系统或配置执行器资格。测试材料是原创合成摘录，原生生成、构建、仿真、CDC、板测均为 **NOT_RUN**。

## 独立行为首轮

八个独立CLI上下文仅取得各自原始材料、请求及冻结r1 Skill，不取得评分标准或其他输出。前六组确实交付12份SVG；第04组两份SVG无效，不能按进程成功计为通过。后两组未擅自出图。

## 修订与复验方式

首轮后只修订相关绘图规则：完整项目规划同时覆盖已有工程；预留走线空隙、避免后画矩形遮字；SVG/PNG须共享布局或直接渲染最终SVG；无法实际查看时报告未复核；复位极性不能从名称或模板推定。

六个失败案例在新目录中按审阅反馈修复，再由其他审阅者核对原始材料与最终SVG/PNG、原尺寸及缩小预览。**这些是带反馈的修复复验，不是六次新的无提示独立通过。** 图稿修好也不等于证明下一份未知工程能一次出图成功；仍需按指南进行事实和图面检查。

另修复共享画布的PNG伪粗体：给中文笔画加描边会粘连，改为使用指定字体本身的字重，SVG保留font-weight。布局/文本不变，重新渲染PNG并检查。公开路径扫描还曾拒绝测试里的合成绝对路径字面量；改为在运行时组合相同负例，没有放宽扫描规则。

| 包与解压 | 三包成员、CRC、SHA-256及负例检查通过；独立解压源码校验、三个只读演练和Skill出图入口通过 |
| 远端CI | NOT_RUN；CI定义已更新，不用本地结果冒充远端结果 |

画布的自动检查涉及转义、正交线、范围端点、真实分支点、越界路径、缺字体/Pillow、写入错误与陈旧PNG。模板再生成相等只证明一致性，不证明电路、时序或可读性。图面的方向、跨域关系、标签遮挡仍由实际来源对照及渲染复核确认。

最后的解压检查发现两项本地检查器问题，原始失败保留：跨平台文本换行不同被逐字节比较误判，后续逐项确认只差CRLF/LF；Windows收集的WSL合并日志没有保留子进程stderr，改由Linux进程分别采集后，缺字体与缺Pillow各得到五条明确PNG_GAP。没有为此修改生产绘图代码、放宽压缩包哈希检查或把缺失PNG计为已渲染。

最终指南/脚本经独立只读复核，未发现交付阻断；最终包从最新清单重建，原始素材与v0.7基线复核保持。公开清单只收录文本源码、SVG、脱敏结果；PNG和原始执行日志留本地。

## 已知局限

- 首轮所有六个出图案例都未完整通过，故不能宣传“自动一次画对”或无审阅交付。
- 修订后的规则配合反馈修图完成案例收尾；没有新一轮无提示全量盲测证明普遍稳定性。
- SVG字体取决于查看器的现有字体；PNG不捆绑字体、不安装渲染器。Linux PNG实际渲染仍未覆盖。
- 图稿不是引脚电气审核、RTOS调度测量或FPGA时序/CDC验证。缺失或冲突事实仍需用户/原始工程补证。
- v0.7及更早原生工具结果保留历史身份；本轮未机械重跑CubeMX、TouchGFX、Vivado或FIFO工具链。
