| 执行 | 实际结果 | 结论 |
|---|---|---|

| 审阅反馈后的新副本补验 | 执行者补齐初始化起跨完整 tick 周期的实际源码测试，并完成新 Debug 构建及漏调用负例 | PASS；明确为 guided follow-up，不是第三次盲测或初次自主完成 |

初始 A 的关键反证是：把累计毫秒缩成 32 位后，执行者原测试仍通过，独立完整周期契约失败。补验仅补充测试与相关验证，不修改既有业务功能、IOC、导航或存储约束。移除更新调用的隔离副本仍能目标构建，但接入检查按缺失调用失败。原始工作区、评分和冻结 Skill 均保留。

截断累计量的变异由独立审阅者注入；执行者的漏调用检查针对已知源码及 CMake 模式，正反例均实际构建，ELF 中的调用差异由独立复核确认。

这些材料证明本次功能经实现、审阅和补验完成；不证明只靠 Skill 指令即可稳定避免漏测。原 13 次结果不与本轮结果合并成全通过。两项首次执行及补验使用相同模型设置，宿主提供的 usage、耗时和工具事件摘要见[结构化记录](validation-v07-release.json)；它们不是账单或统计提效证据。

## 自动检查与包

Windows 普通与 -O 各 142 项 Python 回归通过；Linux 普通与 -O 各 51 项只读入口检查通过。实际统计、Model、Reset 和状态业务源码的主机契约及受控负例通过。

三包分别检查额外成员、缺失成员、内容改变、旧校验值与整包缺失，均按具体原因拒绝；普通和 -O 通过。重复打包字节相同，完整源码包解压后运行自身校验，Skill 包运行只读演练，解压的真实状态源码运行主机契约。原有两包在相同来源下字节不变。

首次源码包自测在深层 Windows 路径触发 206；只减少自测解压目录的冗余外层，保留归档结构和全部内容验证，没有修改系统设置或宣称任意长路径受支持。原失败记录保留本地。

新增 CI 同样覆盖三包、解压入口和源码包主机契约。远端结果查看最终提交的 Actions，不用本地成功替代远端成功；厂商工具不在 CI 中运行。
