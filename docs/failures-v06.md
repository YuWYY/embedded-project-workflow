# v0.6 的失败、修订与保留缺口

以下为真实观察，没有删掉失败后只展示最后一次成功。原始进程日志、工具输出和模型对话留本地；公开仅保留原创案例、脱敏结论及来源身份。

| 观察 | 原因范围 | 处理与复验 |
|---|---|---|
| CubeMX子记录启动失败，汇总生成仍为RUNNING | 适配器未同步活动阶段，属于本轮修复对象 | 在后验前保留同一进程结果，失败形成终态；普通/-O负例及真实A/B回归通过 |
| 初版只读入口拒绝实际XPR重复SimTypes | 解析器把列表型Option当成单值 | 仅对实际解读的单值字段要求唯一，增加真实形态正例；34项四环境检查通过 |
| 默认文本只有Mcu.CPN，部分IOC显示device None | 展示遗漏已有Mcu.UserName | 回退到可确认字段，再无字段时明确未声明；新增文本回归 |
| README首版第三入口为支持表，而非人工改动后续接 | 交付与批准计划的入口不一致 | 改为三个实际请求，分别给最少输入、预期结果和可复制委托；独立复核24个链接及授权措辞通过 |
| 公开2020.2 BD包含重复address_block | 当前严格JSON解析范围不足 | 不用后值覆盖前值，不判上游工程错误；XPR事实保留，整体ERROR公开记录，尚未支持 |
| 首轮CLI请求workspace-write但实际只读拒绝补丁 | 本机评估执行环境 | 保留28次完成答复、2次中断、6次未开始；编辑项未完成。独立写入探针成功后，使用进程级可写参数在新副本重做36次；不改全局配置 |
| 只读概览获取了words，最终回答却省略单位 | 行为说明遗漏，不能由工具内部输出替代用户终点 | 原36保留。只补“数量附已确认原生单位及来源”规则，再进行两次新上下文定向复测，均通过 |

每次修改只针对已观察的机制。未要求所有工程迁移、每个任务加审批或重做全部厂商流程。比较前后版本时应同时阅读[完整结果](../evaluations/v06/results.json)和[验证范围](validation-v06.md)，不能把定向复测混进原36得到更好分数。
