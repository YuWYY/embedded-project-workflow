## 最短试用

显式读取仓库中的Skill主文件，提供隔离工作副本、当前目标和允许改变的范围。普通代码小修改直接按相关指南处理，不要求运行全部示例。

已有RTOS工程先执行 `python -B skills/embedded-project-workflow/scripts/cubemx_rtos.py --help`，从 `doctor` 与 `inspect` 开始；符合窄支持范围后，`plan` 明确对象、目标值、单位和源哈希，`apply` 在独立副本执行真实生成及Rebuild，`verify` 检查生成和链接接入。具体参数以子命令 `--help` 为准。计划不是持久配置源，IOC改变后必须重新分析。

完整占位命令及A/B基线见 [适配器最短调用路径](cubemx-adapter.md)。

固定示例入口分别见 [CubeMX](../examples/cubemx-rtos/README.md)、[TouchGFX](../examples/touchgfx/README.md)、[Vivado](../examples/vivado/controlled-project/README.md)。可选 `--timeout` 是单次子进程等待上限，分别默认360、300、900秒；不是整轮流程总时限。负数、零、NaN及无穷值在写入输出目录前拒绝。

## 验收语义

运行记录从复制/生成前建立，每阶段保留执行状态。失败记录包括失败类型、阶段、真实进程退出码、超时及清理结果；未启动工具的退出码为空。普通失败/超时返回1，参数错误2，受控中断130。原有成功字段和有效判据保持兼容。

日志直接写入本轮文件，异常后保留已有内容。清理只针对本轮仍持有且仍存活的PID及其进程树；清理失败记录不完整。JSON同目录临时写入后原子替换；持续存储故障、断电或强杀仍可能留下旧记录，恢复时必须核对实际源码和产物。Vivado成功所属记录在验收及结果保存后推进。

Keil仍接受退出码0或1且日志零错误，预期链接负例同时匹配失败退出与具体未定义入口。优化模式不能取消检查。编译成功还须检查唯一创建、用户任务入口来自正确对象文件、栈/队列尺寸与最终MAP。

## 本轮结果

本轮约定的最终检查已完成，仍保留下述未覆盖项与原生工具异常；不将有限通过记录表述为工具稳定性保证。源码身份、测试数量、来源哈希及A/B变更见 [机器可读摘要](validation-v03.json)。

- 定向行为复验：5例由新代理执行，未提供评分标准；复核实际差异、命令和只读边界后均通过。五例在同一代理上下文执行；真人续接另由仅收到工程、约定和状态的新代理完成。详见 [行为记录](../evaluations/v03/results-20260930.json)。
- 真人TouchGFX：用户将sampleValue改为readingValue并移到(48,80)，新代理只适配用户View中的三个引用；再由用户移至(56,80)，AI核对配置/用户代码哈希并生成构建。用户随后明确报告递增、双向导航、暂停、恢复和状态保留五项实际交互通过。交互证据来自用户操作反馈，不是代理自动点击或板测。
- Vivado：[最终入口记录](../examples/vivado/controlled-project/validation-v03-20260930.json)中四阶段全部完成，每阶段400采样、两轮复位，125MHz为8ns；三份125MHz的配置/时钟/资源指标一致，40份旧证据归档字节保持。首轮转频发生Tcl_Close与EXCEPTION_BREAKPOINT；诊断副本也有XSim读取脚本异常。原始失败完整保留，最终通过不证明已修复工具根因。
- Windows进程树：真实Python父、子、孙进程被限定清理，独立同一解释器进程保持存活。受控中断是在实际存活进程等待处注入Python KeyboardInterrupt，未覆盖操作系统控制台信号、断电或强杀。

历史FIFO入口和不受本轮修改影响的历史行为证据不重复标成本版重新通过。未运行硬件、板级时序收敛、栈水位或长期稳定性测试。案例观察不支持故障率或效率提升的统计宣传。

## 适配器与独立复核

A实际完成Producer静态栈256→384 words、Samples容量8→16；B实际完成Logger动态栈320→448 words、Frames容量12→20，Sampler静态栈192保持。两次生成和Rebuild均退出0、零错误零警告；入口分别来自rtos_app.o和telemetry_tasks.o。A存储尺寸为1536/1024/64字节；B静态Sampler/Frames为768/80字节，Logger动态属性1792字节。每份工程比较1103份编译输入的构建前后哈希。

实际CLI负例分别修改构建后APP与计划后.mxproject，均因所期望的来源变化退出1；前者不能复用旧产物，后者未进入修改/工具阶段。测试输入按原字节恢复后验证通过。重复对象、未知字段、非支持版本、动态队列、遗漏/弱默认接入、外部引用以及构建期间源变化也有主机拒绝测试。

普通Python与-O分别通过CubeMX19、TouchGFX15、Vivado28、适配器27项测试；Vivado其中4个文件symlink场景因权限跳过。独立复核复现并修复一般wait异常清理、负例退出码、外部依赖来源绑定和构建中源码漂移四项问题，复测无剩余具体阻塞项。另补了MAP交叉引用不能掩盖弱定义的检查。

初期doctor把启动器固定PE版本当产品版本，已改为读取实际StringFileInfo、DB与编译器版本输出；真实生成保持未变化main.c的旧时间戳，因此使用已变化RTOS源、参数、产物和日志证据。空AfterMake记录仅按已支持形态处理，非空动作仍拒绝。这些失败及修订留在本地报告，没有通过放宽RTOS更新、链接或来源检查获得通过。

候选仅做本地校验、自测与打包；GitHub CI配置已更新但未推送执行。旧发行107份来源文件哈希不变；CAP和正式工程没有本轮操作。
