## 修改与接口

- PNG 的 `none` 对应不可见图元正确跳过，scope 标题仍独立呈现。编程与写盘异常继续失败；缺字体或 Pillow 才是明确的 PNG 缺口，旧 PNG 不作为当前输出。
- 所有平台在创建输出目录前拒绝 Windows 保留文件名；普通合法名称保持可用。
- `text()` 追加 `max_width` 和 `line_height`，旧参数与默认行为不变。宽度是诊断区域，不自动换行；行距单位为像素。
- 新增 `block()`，先画背景再画文字；`diagnose()` 只报告局部 T 接触、线路穿普通模块、声明标签溢出和后画不透明矩形遮字，不修改布局、不改变 `save()` 的成功条件和返回字段。
- 绘图指南要求执行者核对当前事实、方向、条件与未知项，并实际查看最终原尺寸和缩小图；完成交付前可以自修。完整规划两图、小修改和只读入口不扩展绘图的范围保持不变。
- 五份可编辑模板使用同一绘图基础，没有工程配置格式、自动布局或端口类型系统。

## 两个真实工程

### STM32：当前源码、参数和图一致

使用已有 F103/CMake 状态页成功工程的隔离副本，保留 ARM GCC 13.3.1、CMake 3.28.1、原 Ninja、64 KiB Flash / 20 KiB RAM、裸机主循环和 Custom Screen 2。不运行 CubeMX 再生成。

A 的实际 `epw_status.c` 主机契约包含连续 42,949,680 次轮询跨越完整 32 位 tick 周期；干净 Debug 构建、编译源、ELF 中 main→init/poll 调用和 MAP 归属通过，进程退出码为 0。Flash 使用 52,328 B，RAM 6,680 B。累计时间与快照发布、UI 绘制分开表达；图中 100 ms 不是屏幕刷新率。

B 由准备脚本仅把配置头的 100→200 ms、Run status→System status 改为明确标记的受控输入，保留 A 图和旧产物。新代理未改固件，更新当前契约与图：199/200/201 ms 边界、迟到只发布一次、回绕和连续 21,474,840 次调用跨完整 tick 周期通过。新 Debug 的预处理、ELF 初始化参数 200、新菜单字符串、主循环调用及 MAP 归属实际核对，Flash 52,332 B / RAM 链接区域使用 6,680 B。

交付前自检保留三次失败：旧固定参数契约不适用于当前值；验证脚本解析 Windows 编译命令失败；预处理检查错误依赖字符串出现次数。执行者修改的是检查脚本，未恢复配置或修改业务以迎合旧断言；最终新目录验证通过。独立复核另直接编译实际业务源码与当前配置头，并执行三个隔离负例；失败日志和旧产物仍保留。输入工程 994 个文件在各执行阶段不变，受控 A→B 仅配置头变化。

源码 SPI 显示路径与上游 README 的 I2C 表述分开记录；图按 IOC 与实际源码表达，不据此确认板上接线。OLED画面、按键电气、真实中断竞态、时钟精度、栈与实时性均未板测。

### FPGA：125→100 MHz 原生维护

器件、IP 与输入固定为案例声明：Vivado 2025.1、Clocking Wizard 6.0、xc7a200tfbg484-2、50 MHz。`clock-config.tcl` 仍是来源，保留五端口、`reset | ~locked` 异步置位和输出域三阶段同步释放的用户 RTL。

| 原生阶段 | 实际结果 | 仿真 | 综合 |
|---|---|---|---|
| beta2-clock125-clean | Vivado 0；120.7 s | 400 周期 / 两轮复位 / 8 ns | IP OOC + 顶层完成 |
| beta2-clock100-regenerate | Vivado 0；100.34 s | 400 周期 / 两轮复位 / 10 ns | IP OOC + 顶层完成 |
| beta2-clock100-clean | Vivado 0；100.31 s | 400 周期 / 两轮复位 / 10 ns | IP OOC + 顶层完成 |

真实工具每子进程上限为900秒，没有自动循环重试。A 发生外层 Tee 日志路径错误，原生阶段内部日志和退出码完整，Python runner自身退出码未可靠采集。B 再生成也发生外层 Tee 错误，监视取得 runner=120，而已原子保存的原生结果是 Vivado=0；没有捕获 Python 最终异常堆栈，因此不把管道解释当作已证实根因。B 空目录构建 runner=0、Vivado=0。**三个原生阶段确已完成，但不能宣称所有外层进程均成功。**

两份100 MHz XCI/生成HDL为 M=20、D=1、O=10；实际报告为10 ns。两个构建根的六项当前源与记录绑定一致；对阶段A只变配置125→100，RTL、TB、XDC和入口均未修改。旧125 MHz阶段产物保留，不能证明当前100 MHz；两图已更新频率、域说明和同版身份。

TB 使用2～4边沿窗口观察释放，**不是精确三拍的独立仿真断言**；三阶段结构由实际 RTL/综合网表补充支持。两轮复位不等于独立注入失锁或停钟。XDC没有 PACKAGE_PIN、IOSTANDARD、完整输入/输出延迟；图只确认五个逻辑端口，物理分配待确认。综合报告不能证明布局布线时序、亚稳态、完整CDC或板级运行。

## 原始失败与已知局限

- 旧 CLI 预检失败两次：默认模型不适用于当前账号，当前配置模型要求更高 CLI。没有安装或升级，也没有开始整批正式评估；改用当前宿主的新上下文代理，读/写/读回及图像查看预检成功，才开始11项正式任务。这些预检不算行为通过或失败。
- 早期保留文件名测试用 `NUL` 本身作为 Windows 测试目录，触发特殊文件存在语义；保留原失败，改为普通父目录后检查产品是否提前拒绝。没有把测试夹具失败包装成产品修复。
- 几何诊断会漏掉三条线都以同一坐标为端点的无圆点 T 接头；本轮承诺只检测“端点碰另一条线中段”。合法输出仍须查看，空诊断不证明无错。字体矩形也不是逐像素图形求交。
- STM32接续者的本地交接说明把契约脚本适用范围写成 `1<period<1000 ms`，独立复核发现这过宽：迟到场景先给 `3*p+57` 再给 `4*p`，当 `p<57` 时会产生非预期时间倒退。本轮100/200 ms结果成立，但脚本只能按已验证案例使用，不能据原说明承诺任意该区间参数。原交付和复核说明分别保留，没有倒改首次结果。
- 浏览器对大图可能自动缩小，因此结合原尺寸截图、缩图与必要局部实际查看。SVG与PNG共用布局，不宣称不同字体引擎像素一致。
- 可选浏览器缓存清理曾被自动策略拒绝，缓存保留本地，不绕过、不计为输出缺失，也不收入候选包。
- 真人新用户体验、Linux PNG、硬件、实现/bitstream、Vitis A53软件构建和ESP-IDF原生构建仍未覆盖。原始工具警告与历史 Tcl_Close / XSim 问题不因本轮成功而宣布根因修复。
